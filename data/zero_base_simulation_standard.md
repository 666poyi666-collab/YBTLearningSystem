# 零基础学生模拟与学习路径验收标准

本标准用于每个小节、每个学习任务和每一代路线修订。它是路线验收标准，不是答案册，也不把代理结果写入真人掌握账本。

## 一、输入边界

- 学生模拟器只消费 `student_packet`、无答案课程路线、已验证的视觉侧车和课程转写。
- **看视频 = 读视频文稿**：模拟学生必须先把当前循环 `course_keys` 对应课程的文稿（`data/course_transcripts/*.json`）完整当作视频内容阅读，再作答该循环题目；没有文稿的课程不得凭标题推断覆盖，只能判 `BLOCKED`。
- 禁止读取 `answer_sidecar.json`、答案 OCR、答案正文、教师判卷结果或历史最终答案。
- 题目和课程必须带当前代的内容哈希；旧代报告不能证明新代路线。
- 图形状态为 `NEEDS_VISION_SIDECAR`、`MISSING_OCR_ANCHOR` 或 `UNVERIFIED` 时，模拟器必须停止并记录阻断，不能猜图。

## 二、每道题的模拟动作

学生完成每道题时必须依次记录：

1. **观察信号**：题目中的设问、几何关系、数量关系或关键词是什么。
2. **课程调用**：听过哪门课，课程中的哪个定义、公式或方法模型能处理这个信号。
3. **第一行**：先写目标量、目标向量、参数或合法截面，不直接跳结论。
4. **第二行**：写定义、向量表示、系数关系、数量积或参数方程，并说明依据。
5. **继续动作**：每次只推进一个可解释的等式或几何关系。
6. **独立自检**：检查方向、符号、定义域、范围、非零条件、等号条件和题目对象是否对应。
7. **第一断点**：一旦无法继续，只记录最早卡点，不能让教师替学生补完整解法。

例题允许在教学阶段跟随完整过程；直属变式和 A/B/C 题必须隐藏答案并独立作答。变式还必须记录“相对母题改变了什么”。

## 三、证据等级

| 等级 | 含义 | 能否称为掌握 |
|---|---|---|
| `ROUTE_CONSUMED` | 学生能找到当前课程、知识点和任务入口 | 不能 |
| `SAME_SESSION_WORKFLOW_PASS` | 同一会话中能按路线独立写出过程 | 不能 |
| `PROMPTED_CORRECTION` | 得到最小提示后修正 | 不能，必须复测 |
| `UNSEEN_TRANSFER_PASS` | 未见近变式中独立迁移，且有题目指纹和上下文哈希 | 不能，仍需延迟复测 |
| `COLD_RETEST_24H_PASS` | 至少间隔 24 小时、无答案、无提示重新完成 | 可作为掌握门的一部分 |
| `HUMAN_OBSERVED` | 真人按协议完成课程、作答、复述和冷复测 | 才能进入真人验收 |

代理模拟最多产生 `SAME_SESSION_WORKFLOW_PASS` 或 `UNSEEN_TRANSFER_PASS`。任何代理结果都必须带 `human_acceptance_not_proven=true`，不能填充真人观察文件或直接触发奖励状态。

## 四、单题判定

- `PASS`：观察信号、方法调用、过程书写、自检全部成立，且没有提示污染。
- `PARTIAL`：能进入方法，但在第一断点停止、依赖补充桥接，或过程缺少关键依据。
- `BLOCKED`：题面、视觉、课程转写、桥接或题号证据不完整。
- `FAIL`：调用了错误方法、出现不可解释跳步，或在没有题面依据时猜图。

每个结果必须记录：`section`、`cycle`、`item_id`、`source_revision`、`context_sha256`、`first_breakpoint`、`hint_level`、`answer_sidecar_read=false`、`human_acceptance_not_proven=true`。

实现时，当前代汇总必须同时提供 `item_results` 数组，且每个题项只出现一次。每个元素固定包含：
`observation_signal`、`course_call`、`first_line`、`second_line`、`continuation`、
`independent_self_check`、`first_breakpoint`、`hint_level`、`verdict`；其中
`course_call.method_model_id` 用来记录“听过的课程方法如何被调用”，不能只写循环级自由文本。
`source_revision.generation` 必须等于汇总的 generation，`context_sha256` 必须是当前学生上下文的
64 位 SHA-256。`item_results` 的键集合必须与当前 packet 中的教学例题、直属变式和 A/B/C 题逐项相等，
否则只能判为 `BLOCKED`，不能用 `task_coverage.complete=true` 的汇总字段替代逐题证据。

## 五、多代打磨流程

每一代必须完整执行：

1. 源书页序、课程转写和题号清单对账。
2. 按“知识点 → 右侧例题 → 直属变式 → 类型题 → A/B/C”生成路线。
3. 代理逐题模拟，记录第一断点和重复卡点。
4. 主控只修正有证据的问题，不用代理答案覆盖源材料。
5. 重新生成 student packet、课程依赖、Markdown 和 HTML。
6. 独立代理复核新代内容哈希、题目覆盖和无答案边界。
7. 重新跑完整性、OCR、视觉、课程哈希、答案隔离和浏览器测试。

任何题目新增、删除、题号改变、OCR 派生修正或课程依赖改变都必须提升代号，并重新跑完整门禁。测试通过但题包或报告仍引用旧哈希时，代次状态为 `STALE`，不能发布。
