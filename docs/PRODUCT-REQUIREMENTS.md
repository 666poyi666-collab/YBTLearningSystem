# 一本通第一、二章学习产品需求

## 1. 产品目标

针对用户指定的《一本通》节次，先完整理解教材结构，再从批准课程中核验真实覆盖，生成可执行、紧凑的学习路径。近期只完成并迭代第一章和第二章，用这两章逐步校准一个专门模拟当前用户的持续成长学习者。

## 2. 用户场景

用户按节学习，不会一次完成五章。系统需要回答：

- 这一节实际由哪些知识块、右侧例题、类型例题、对应变式和强化训练组成？
- 批准课程中的哪些具体视频真正覆盖这些内容？
- 应按什么顺序听课、看例题、做变式和进入强化训练？
- 本章需要的课程是否全部覆盖、模拟学习者是否全部学完、真实用户是否全部学完？
- 用户在哪里卡住，画像因此发生了什么有证据的变化？

## 3. 教材结构原则

“知识点与右侧例题、类型题与对应变式、强化训练”是常见结构，不是强制套用的三段模板。每节必须以真实教材版面为准：

1. 先通读该节全部 OCR 页面、图像、manifest 和 packet。
2. 识别知识块与紧邻例题、类型块、例题与变式的父子关系，以及 A/B/C 或其他强化训练边界。
3. 保持教材原顺序。不得为了适配预设结构移动、合并或重复题项。
4. 完成教学性内容和直接迁移后，再进入该范围对应的强化训练与验收。

## 4. 课程覆盖与学完

课程判断必须阅读转写正文，不能根据标题猜测。

- `coverage=covered`：课程内容能够教授对应教材知识或方法。
- `scheduled`：课程已进入学习路径，但学习者尚未消费完成。
- `simulated_completed`：持续学习者已消费绑定转写，并留下完成证据。
- `user_completed`：真实用户完成；代理记录不能填写该状态。
- `blocked`：课程文件、转写或必要证据不可用。

每章必须输出去重后的必修课程账本。若模拟学习者未学完，列出所有未完成课程；若全部学完，明确标记“模拟课程已完成”。真实用户状态单独显示。

## 5. 智能体职责

### 5.1 路线构建智能体

负责教材重建、课程覆盖、学习循环、题项核账和紧凑交付。它可以按节并行，但不得伪造学习者进度。

### 5.2 五人格压力测试

保留五种固定零基础困难作为内部回归：字面执行弱、方法识别弱、代数操作弱、图形转换弱、自检弱。它们用于发现路线的系统性缺口，逐题尝试只写入机器 JSON，不进入面向用户的正文。

### 5.3 持续成长的学习者

`primary-user-proxy` 专门模拟当前用户，并在章节合并后按教材顺序单线程运行：

- 初始只知道“尽可能按零基础处理”，不预设具体弱点。
- 学完课程后再尝试对应教材项目。
- 每次作答先冻结，再评价；不得读取答案侧车、其他人格答案或教师结论。
- 只有实际卡点、提示依赖、纠错结果和自检表现才能更新画像。
- 画像跨节保留版本历史，不因进入下一节而重置。
- 代理完成不等于真实用户完成或 24 小时冷复测通过。

### 5.4 验收职责

路线压力测试和持续学习者不能自证最终完成。机器校验负责结构与证据一致性；真实用户学习和延迟复测保持独立状态。

## 6. 执行顺序

1. 完成第一章所有节次的教材与课程覆盖审计。
2. 生成第一章紧凑学习路径和课程账本。
3. 运行五人格内部压力测试并修订路线。
4. 让持续学习者按第一章教材顺序学习、作答、更新画像。
5. 列出第一章未学课程和未通过项目；全部闭合后标记代理章完成。
6. 携带第一章形成的画像进入第二章，重复同一流程。
7. 第三至第五章等待用户明确扩大范围。

## 7. 面向用户的交付格式

机器证据与学习文稿分层：

- JSON 保留逐题方法、25 次压力测试记录、哈希和视觉证据。
- Markdown/HTML 不展示人格流水账、内部 ID、哈希和重复的七字段段落。
- 章首显示课程完成账本、未完成课程和各节状态。
- 节首显示课程顺序与教材地图。
- 每个教材循环只写一次共享方法；题目列表保证覆盖，单题只写差异提示。
- 页面应能快速回答“现在看什么课、接着做哪些题、何时进入强化训练、哪里尚未通过”。

## 8. 成功标准

第一、二章分别满足以下条件才可标记对应的代理章完成：

- 所有 canonical 项目在教材顺序中出现且仅出现一次。
- 每个项目至少有一个已核验课程调用，或明确记录课程覆盖缺口。
- 必修课程账本没有未完成课程。
- 五人格压力测试通过当前机器门禁。
- 持续学习者尝试全部项目，未通过项目为空。
- 持续学习者画像版本与尝试证据闭合。
- learner-facing 文稿通过答案泄漏、内部 ID 和紧凑结构检查。

真实用户完成与 24 小时冷复测不包含在“代理章完成”中，必须另行报告。

## 9. 学习页面交互补充

- 节次标题使用教材原题名；节首默认显示紧凑总览。
- 章节看板与小节工作区必须分层：章节看板只显示本章课程、教材项目、节次和循环进度；切换节次后，小节工作区只显示当前节的课程、循环和题目。
- learner-facing 看板不得显示“课程覆盖项目”“模拟已学课程”或“真实用户”等内部合同文案；教材项目必须明确表达为“已通过/总数”。
- 本节课程使用纵向表格，序号、课程编号、课程名称和状态分别成列，不得把行号、课程节次号和课程标题连接成一段。
- 桌面端采用学习工作台：左侧节次导航、中间纵向学习路线、右侧课程队列；不得使用横向堆满的循环标签导航。
- 循环路线使用连续编号和时间线表达顺序；循环标题独占一行，课程与题序在下方分区展示，不能把标题、课程和题号挤成同一行。
- 点击循环进入独立全宽详情，必须提供清晰的“返回本节学习路线”；移动端先展示纵向课程队列，再展示学习路线。
- 每个循环必须直接显示带章节编号的课程、教材题目顺序，以及“循环已听完”切换。
- 用户可以为循环和单题加星标；星标、循环听完状态和循环疑问在浏览器本地持久化。
- 单题可标记“项目已通过”；章节教材项目进度和节次完成状态由题目通过与循环听完记录计算。
- 每个循环提供疑问输入和“复制给 ChatGPT”操作，复制内容只包含当前循环的课程、题序和用户疑问，不携带答案侧车或内部题目 ID。
- 章节循环进度由已标记听完的循环计算；它与课程覆盖、题目通过、代理完成和真实用户完成保持独立。

## 10. ChatGPT 辅助闭环

- GitHub 连接是仓库事实来源；用户不需要每次下载仓库或上传整个仓库压缩包。
- 旧的 8.5 ChatGPT 对话只作为交互参考，建议上传到 ChatGPT 项目作为私有项目来源，不提交到公开 GitHub。
- 网页的“复制给 ChatGPT”必须携带当前循环、课程、题序和用户疑问，并要求模型先判断卡点、给最小提示、等待用户尝试。
- 当前阶段不引入 MCP；只有需要模型自动读取/写回进度和画像时，才评估后端 API 或远程 MCP。
